# Operational Status Integration

## 目的

Disney Planner が「今現在の状態」ではなく、設定された来園日の公式運営情報を基準にプランを生成する。

## アトラクション

- `operatingStatus`
- `closureStartDate`
- `closureEndDate`

をハード制約として扱う。
休止日の施設は候補スコアリング前に除外する。

`scheduledClosure` は休止期間内だけ利用不可とし、終了日後は再び候補にできる。
`longTermClosed` / `permanentlyClosed` 等はマスター更新まで候補から除外する。

## レストラン・ショップ

日付別運営時間は各施設のマスターに `operatingSchedules` で保持できる。

```json
"operatingSchedules": {
  "2026-08-18": [
    {"open": "11:00", "close": "13:00"},
    {"open": "14:00", "close": "20:00"}
  ]
}
```

複数の営業枠にも対応する。

来園日が設定されている場合、レストラン・ショップの公式運営時間が未登録なら、
自動プランは営業時間を推測しない。誤った時間に配置するより候補から外す。
ただし利用時刻が確定した予約は例外として保持する。

## データ更新

公式情報の確認元:
- 東京ディズニーリゾート各パークのアトラクション/休止情報
- レストラン一覧の「運営時間を調べる」
- ショップ一覧の「運営/公演予定」

公式情報は予告なく変更されるため、当日はTodayのライブ運営情報を優先する。

## 重要

マスターに運営時間がないことは「終日営業」を意味しない。
`unknown = operating` と推測しないことを基本原則とする。
